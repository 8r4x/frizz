Per-message timestamps, on hover

Font

Four placements for the same fact. The data already ships — TranscriptMessage.at is an ISO8601 the server sets on both providers and the client already reads — so each of these is a pure client render, no schema change and no server round-trip. All four are zero-layout by construction: the transcript is virtualized, so a reveal that changed a row's measured height would shove the scroll position under the pointer. Hover the messages below — every panel is blank at rest, which is the point; each variant only shows its reading under the pointer.

ATooltip on the message

Zero chrome. The message body is the trigger and the reading arrives in the app's existing dark tooltip, with the full date, the seconds and the age. Cheapest to ship — components/Tooltip.tsx already exists — and the only variant that adds literally nothing to the layout. Its weakness shows the moment you hover: the tip is drawn over the transcript, so reading one message's time hides the one above it, and an unmarked trigger is undiscoverable, so nobody finds this without being told.

BReserved gutter

A permanently-present 56px column, blank until you hover a row. Every reading lands on one x, so running the pointer down the transcript reads as a column of times — and a modifier key could light the whole column at once, which no other variant supports. The cost is visible without hovering anything: the transcript loses 56px on every row forever for a reading that is blank almost always, and the user bubble below wraps where the other three variants fit it on one line. A message not from today shows its date instead of its clock, which is all that fits.

CTrailing reveal — chosen

The reading fades in at the message's own trailing edge, laid over the page so it costs no width and no height. It belongs to that message, which is exactly the question being asked, and unlike the tooltip it hides nothing. The cost is that it appears in a different place on every row, so comparing three of them is three separate looks. It carries the DATE on every reading, not just the clock: a worker can be parked on a PR watcher for days, so two adjacent messages routinely sit on different dates and a bare 10:31 AM cannot say which. The year is added only when it is not the current one.

DHairline reveal

Hovering draws the transcript's own section-break rule above the message, carrying the time as a petite-caps label — the vocabulary the wake dividers already taught the reader. It marks the whole top edge and needs no learning. It is also the loudest of the four for the smallest fact, and it borrows a chrome that elsewhere means something happened here: hover the last message and watch a second hairline stack under the real divider.
